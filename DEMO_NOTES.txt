ESTATEPILOT AI - DEMO NOTES (read before presenting)
=====================================================
Purpose: list every place where the demo may look "broken" or ask for
credentials, so nothing surprises you in front of an audience.

IMPORTANT: The app NEVER asks for an email password. Gmail uses Google's OAuth
login popup. For the demo you do NOT need Gmail at all - use pasted / demo
emails. They go through the same AI pipeline.


1. WHAT WORKS WITH ZERO CREDENTIALS (safe to demo)
--------------------------------------------------
- Login (agent@demo.com / Passw0rd!demo)
- Inbox: "Paste email" and "Load demo emails" -> classify, extract, lead,
  score + reasons, property matches, reply draft, follow-up task
- Lead / Property / Follow-up create, edit, archive, search, CSV export
- Property matching (against the stored demo properties only)
- Automation Center: pause/resume, rule toggles, kill switch (admin only)
- Activity / audit logs, Overview dashboard, Analytics charts + CSV export
- Duplicate email protection (pasting the same email twice -> "duplicate")

3. WHAT IS NOT VERIFIED (do not claim in the demo)
--------------------------------------------------
- Live Gmail connect / sync / send   (tested only with mocks)
- Real OpenAI or Gemini output       (tested only with mocks)
- PostgreSQL, Docker / docker-compose (never run)
- Power BI report, DAX, embedding    (files only, no PBIX)
- Windows commands                    (not run on Windows)
- Browser UI click-through            (API + unit tests verified; no browser
                                       test was run - click through once yourself
                                       BEFORE the demo)
- It is a local MVP, NOT production-secure or enterprise-ready.
- No accuracy / performance numbers exist. Do not quote any.


4. PRE-DEMO CHECKLIST (5 minutes before)
----------------------------------------
[ ] Backend running: http://localhost:8000/health shows "status":"ok"
[ ] Frontend running: open http://localhost:5173 (use "localhost", NOT 127.0.0.1)
[ ] Log in as agent@demo.com / Passw0rd!demo
[ ] Fresh DB for a clean demo (see HOW_TO_RUN.txt "Reset the database")
[ ] Have the example email ready to paste (below)
[ ] Do one full dry run first; the same email can only be imported once
    per database, so reset the DB (or change the text/sender) afterwards
[ ] Close tabs showing .env or terminals with secrets
[ ] Never put real keys/passwords in the project folder before sharing

6. IF SOMETHING GOES WRONG LIVE
-------------------------------
- Page shows API / network error  -> backend not running; restart it
                                     (HOW_TO_RUN.txt step 1)
- Blank page / CORS error         -> you opened 127.0.0.1; use localhost:5173
- "automation paused" message     -> Automation Center -> Resume
                                     (or kill switch is on: admin turns it off)
- Email stuck in "failed"         -> click Process / Retry (safe to retry)
- Login rate-limited              -> wait a minute and retry
- Say calmly: "This is a local MVP; that integration needs credentials I
  haven't configured for this demo."
